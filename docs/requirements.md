## 1. 이해관계자

| 구분 | 정의 | 주요 관심사 |
|---|---|---|
| 방문자 | 로그인하지 않은 사용자 | 어떤 모임이 열리는지 둘러보고 가입 여부 판단 |
| 이용자 | 소셜 계정으로 가입한 사용자 | 모임 참여, 참여자와의 대화, 내 활동 관리 |
| 모임 개설자 | 모임을 만든 이용자 | 모임 정보 관리, 참여자 관리 |
| 서비스 관리자 | 공지 권한을 가진 운영 주체 | 공지 게시, 서비스 안내 |
| 시스템 운영자 | 배포·모니터링 담당 | 가용성, 확장, 장애 대응 |

## 2. 용어 정의

| 용어 | 정의 | 대응 개념 |
|---|---|---|
| **모임** | 특정 장소에서 함께 식사할 사람들의 모음. 게시글 형태로 노출 | `Team` |
| **개설자** | 모임을 만든 사람. 해당 모임의 관리 권한을 가짐 | `AccountTeam.isLeader = true` |
| **참여** | 이용자가 모임의 구성원이 되는 것 | `AccountTeam` 생성 |
| **모임 채팅방** | 모임마다 1개씩 자동 생성되는 전용 대화 공간 | `ChatRoom` (모임과 1:1) |
| **대화 내역** | 채팅방에 축적된 과거 메시지 | `ChatMessage` (TALK 한정) |

## 3. 사용자 요구사항

### 3.1 가입과 로그인

#### UR-01 ✅ 충족
> 방문자는 별도 회원가입 절차 없이 보유한 소셜 계정으로 서비스를 이용하고 싶다.

**인수 기준**
- 카카오 · 네이버 · 구글 중 하나를 선택해 로그인할 수 있다
- 최초 로그인 시 계정이 자동 생성되며, 별도 정보 입력을 요구하지 않는다
- 소셜 계정의 이름이 초기 표시 이름이 된다

#### UR-02 ✅ 충족
> 이용자는 서비스에서 사용할 표시 이름을 소셜 계정과 별개로 정하고 싶다.

**인수 기준**
- 표시 이름을 변경할 수 있고, 변경 즉시 화면에 반영된다
- 다시 로그인해도 소셜 이름으로 되돌아가지 않는다

#### UR-03 ✅ 충족
> 이용자는 서비스 이용을 그만둘 때 계정과 활동 이력을 지우고 싶다.

**인수 기준**
- 탈퇴 시 계정, 모임 참여 이력, 작성한 공지가 함께 삭제된다
- 탈퇴와 동시에 소셜 로그인 연결도 해제된다

### 3.2 모임

#### UR-04 ✅ 충족
> 이용자는 만날 장소를 지도에서 찾아 지정하고 모임을 개설하고 싶다.

**인수 기준**
- 장소명을 검색해 지도에서 선택할 수 있다
- 선택한 장소의 이름 · 주소 · 전화번호가 모임 정보에 함께 저장된다
- 개설과 동시에 전용 채팅방이 만들어지고, 개설자가 자동으로 참여자가 된다

#### UR-05 ✅ 충족
> 방문자는 로그인 없이도 어떤 모임이 열려 있는지 둘러보고 싶다.

**인수 기준**
- 로그인하지 않아도 모임 목록과 상세를 볼 수 있다
- 모임 이름 · 장소명 · 주소로 검색할 수 있다
- 목록에는 개설자, 현재 참여 인원, 개설일이 표시된다

#### UR-06 ✅ 충족
> 이용자는 마음에 드는 모임에 참여하고 곧바로 대화에 합류하고 싶다.

**인수 기준**
- 참여 즉시 해당 모임의 채팅방으로 진입할 수 있다
- 이미 참여한 모임에 다시 참여를 눌러도 중복 등록되지 않는다

#### UR-07 ⚠️ 부분 충족
> 개설자는 자신이 만든 모임의 정보를 고치거나, 모임을 닫거나, 부적절한 참여자를 내보내고 싶다.

**인수 기준**
- ✅ 모임 정보 수정 · 삭제 · 참여자 강퇴 기능이 동작한다
- ❌ **개설자 본인만** 해당 작업을 수행할 수 있다 → [ISS-01](known-issues.md#iss-01)

#### UR-08 ✅ 충족
> 이용자는 내가 참여 중인 모임을 한눈에 보고, 원하면 나가고 싶다.

**인수 기준**
- 내 프로필에서 참여 중인 모임 목록을 볼 수 있다
- 내가 개설한 모임과 단순 참여 모임이 구분되어 보인다
- 모임에서 나갈 수 있다

### 3.3 대화

#### UR-09 ✅ 충족
> 참여자는 같은 모임 사람들과 실시간으로 대화하고 싶다.

**인수 기준**
- 보낸 메시지가 다른 참여자 화면에 즉시 나타난다
- 누가 들어오고 나갔는지 알 수 있다
- 현재 몇 명이 접속해 있는지 표시된다

#### UR-10 ✅ 충족
> 참여자는 잠시 자리를 비웠다 돌아와도 그동안의 대화를 확인하고 싶다.

**인수 기준**
- 채팅방에 다시 들어오면 최근 대화가 그대로 보인다
- 화면을 새로고침해도 대화가 사라지지 않는다
- 서비스가 재시작되어도 대화가 보존된다
- 위로 스크롤하면 더 이전 대화를 이어서 볼 수 있다
- 입장 · 퇴장 알림은 내역에 쌓이지 않아 대화 흐름을 방해하지 않는다

#### UR-11 ✅ 충족
> 참여자는 대화 내용이 모임 구성원 외부에 노출되지 않기를 바란다.

**인수 기준**
- 해당 모임의 참여자만 대화 내역을 조회할 수 있다
- 참여자가 아니면 접근이 거부된다

> ⚠️ 대화 **내역 조회**에는 멤버십 검증이 적용되어 있으나, **실시간 구독**(STOMP SUBSCRIBE)에는 없습니다. → [ISS-01](known-issues.md#iss-01)

#### UR-12 ✅ 충족
> 참여자는 과거 대화에서 누가 말했는지가 당시 이름 그대로 남아 있기를 바란다.

**인수 기준**
- 발신자가 이후 표시 이름을 바꿔도 과거 메시지의 이름은 변하지 않는다
- 발신자가 탈퇴해도 메시지 자체는 남는다

### 3.4 공지 · 기타

#### UR-13 ✅ 충족
> 서비스 관리자는 이용자에게 안내 사항을 공지하고 싶다.

**인수 기준**
- 관리자만 공지를 작성 · 수정 · 삭제할 수 있다
- 누구나 공지를 열람하고 제목으로 검색할 수 있다

#### UR-14 ❌ 미충족
> 이용자는 내가 신청한 모임과 참여 중인 채팅방을 프로필에서 모아 보고 싶다.

**인수 기준**
- ❌ 신청 모임 목록 화면이 실제 데이터를 표시한다 → [ISS-05](known-issues.md#iss-05)
- ❌ 참여 채팅방 목록 화면이 실제 데이터를 표시한다 → [ISS-05](known-issues.md#iss-05)
